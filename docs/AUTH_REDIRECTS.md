# SolidDesign Auth Redirect Configuration

**Status:** current runtime contract  
**Date:** 2026-08-29

## Purpose

Supabase Auth email flows must always return users to an approved SolidDesign **internal** origin. Auth redirects are deployment configuration, not user/prospect identity.

A stale/local Supabase Site URL must never determine a production invitation destination.

## Application contract

`team-invite` always passes an explicit `redirectTo` to `supabase.auth.admin.inviteUserByEmail`.

Allowed runtime origins are deliberately narrow:

```text
https://soliddesign-cms.pages.dev
https://pr-<number>.soliddesign-cms.pages.dev
https://cms.<brand>.nl        # after brand cutover, configured explicitly
```

The Edge Function validates the browser `Origin` before using it as an invitation destination. Arbitrary origins are rejected; there is no open-redirect fallback.

This means the environment from which the operator presses **Uitnodigen** intentionally determines the activation return environment. Production invites return to production; PR-preview invites return to that exact PR preview.

PR previews share the same operational Supabase state plane during this rollout, so they can look deceptively similar to production. Every `pr-<number>.soliddesign-cms.pages.dev` Operator UI must therefore display an explicit `TEST · PR-<number>` marker and prefix the browser title. Production must not display that marker.

The future custom CMS hostname is supplied to the Edge Function through:

```text
SOLIDDESIGN_INTERNAL_ORIGIN=https://cms.<brand>.nl
```

Do not infer internal redirect destinations from prospect/public domains.

## Required Supabase Auth configuration

Hosted project: **Authentication → URL Configuration**.

Current rollout:

```text
Site URL
https://soliddesign-cms.pages.dev/

Additional Redirect URLs
https://soliddesign-cms.pages.dev/**
https://pr-*.soliddesign-cms.pages.dev/**
```

The preview wildcard is only for isolated PR verification in the same Cloudflare Pages project. Production should use the exact production Site URL.

After the final brand/domain decision:

```text
Site URL
https://cms.<brand>.nl/

Additional Redirect URLs
https://cms.<brand>.nl/**
```

Keep the old internal hostname temporarily only while a deliberate login/invite cutover requires compatibility; remove it when that transition is verified.

`http://localhost:3000` is a local-development value and must not remain the hosted project's production Site URL.

Supabase requires `redirectTo` destinations to match the configured Redirect URL allow list. The Site URL is only the fallback when application code provides no explicit redirect.

Reference: https://supabase.com/docs/guides/auth/redirect-urls

## Email template rule

Use Supabase's standard `{{ .ConfirmationURL }}` for the invite template unless there is an observed need for a custom confirmation endpoint. `ConfirmationURL` carries the validated `redirect_to` generated by Auth.

If a future template is customized to construct its own destination, it must use `{{ .RedirectTo }}` rather than hard-coding `{{ .SiteURL }}` as the application destination.

Do not create a custom token-exchange/auth service merely to solve ordinary hosted redirects.

## Verification gate

Before M1 invite/onboarding is marked browser-verified:

1. verify the visible environment marker before inviting;
2. invite from the production/internal origin and confirm the email returns there;
3. invite from `pr-<number>` and confirm the email returns to that exact preview origin;
4. confirm an unapproved Origin cannot mint an invitation redirect;
5. finish first-password setup and verify `joined_at` is recorded only afterward;
6. repeat the test after a future `cms.<brand>.nl` cutover before removing the old internal origin.

## Invariant

> Authentication redirects follow the approved internal SolidDesign environment from which the invitation is created. Production and PR previews are visibly distinguishable; redirects never depend on a stale localhost Site URL and never follow arbitrary caller-supplied destinations.
