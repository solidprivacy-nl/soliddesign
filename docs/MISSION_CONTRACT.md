# Mission Contract

**Status:** authoritative for Phase 1

## Mission

SolidDesign exists to find established local businesses with existing commercial demand but measurable website/conversion leakage, create a credible improvement proof before purchase, and learn whether that proof can be converted into profitable customers.

## Mission outcome

The Phase-1 mission is achieved when we can demonstrate, with real prospects rather than synthetic assumptions, that the following loop is operationally repeatable and commercially testable:

```text
DISCOVER
→ QUALIFY
→ AUDIT
→ HUMAN SELECT
→ VERIFIED FACTS
→ CONVERSION BRIEF
→ DEMO
→ REVIEW
→ PREVIEW
→ PRINT PACK
→ PHYSICAL MAIL
→ HUMAN SALES
→ CUSTOMER / LEARNING
```

## What we are optimizing

The system optimizes for **trustworthy commercial learning**, not maximum automation.

Primary economic objective:

> **Gross profit per 100 qualified prospects**

Supporting metrics:

- cost per qualified prospect;
- human minutes per prospect pack;
- demo production cost;
- physical-mail cost;
- demo visit rate;
- response rate;
- meeting rate;
- proposal rate;
- close rate;
- actual delivery hours;
- project gross margin;
- recurring gross profit.

## Mission invariants

1. **Solid but simple.** Complexity needs observed evidence.
2. **No overengineering.** No infrastructure may be added because it is fashionable, scalable in theory, or architecturally elegant.
3. **First-principles reasoning.** Build or reuse only what reduces total cost to reliable learning.
4. **Reuse where semantic fit is high.** Imported code is not automatically simpler than new code.
5. **Functions before agents.** Deterministic work stays deterministic.
6. **Human sales in Phase 1.** No autonomous cold e-mail, AI calling, SMS, WhatsApp or autonomous closing.
7. **External websites are untrusted data.** Website text never becomes instruction authority.
8. **Verified business facts only.** No invented services, testimonials, claims, awards or credentials.
9. **Pre-sale proof is not production delivery.** The demo needs to win attention and a conversation; it does not need to solve every eventual production requirement.
10. **Measure from prospect one.** No retrospective economics guessing.

## Non-goals for Phase 1

Phase 1 explicitly does not aim to build:

- a generic agency SaaS;
- a multi-tenant customer platform;
- a large CRM;
- a complex queue fabric;
- an agent zoo;
- autonomous outreach;
- a universal production website factory;
- a perfect Dutch company-discovery engine;
- a ChatGPT Business/MCP integration;
- a Cloudflare capability gateway before operator need exists;
- advanced machine-learning scoring.

## Stop conditions

We stop adding platform capability when it does not directly improve one of:

- prospect quality;
- proof quality;
- acquisition cost;
- response/meeting conversion;
- delivery margin;
- operational reliability.

The commercial model is reconsidered rather than further automated if repeated real-market tests show weak attention, weak response, low willingness to pay, or structurally poor delivery economics.
