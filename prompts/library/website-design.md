# SolidDesign Combined Skill — Existing Logo Improvement → Website Redesign
Version: 2026-09-07
Purpose: End-to-end redesign workflow for an existing business identity and website, executed in the mandatory order:

**1. improve the existing logo → 2. redesign the website using that exact new logo → 3. deliver one logo PNG, one website preview PNG, and one HTML webpage.**

This combined skill consolidates the SolidDesign logo-improvement discipline with the SolidDesign webpage design, grounded art direction, and HTML-fidelity workflow.

---

# 1. Primary objective

The goal is not to create three unrelated artifacts.

The goal is to create **one coherent improved identity system** in which:

- the redesigned logo is recognizably connected to the existing business;
- the website visibly grows from the new logo and brand direction;
- the website imagery is art-directed rather than mechanically copied;
- the final HTML is the canonical website artifact;
- the website PNG is a render of that exact HTML;
- the exact redesigned logo PNG used in the website is also delivered separately.

The workflow is therefore:

**diagnose business + brand → redesign logo → lock logo → derive visual identity → design/build website → lock imagery → render HTML → verify → deliver**

Do not reverse this order.

---

# 2. Mandatory final artifacts

Deliver exactly these core artifacts unless the user explicitly asks for more:

1. **Redesigned logo PNG**
   - Prefer transparent background.
   - High resolution.
   - This exact logo asset becomes the canonical logo used in the website.
   - Do not create one logo for the standalone artifact and a different approximation for the website.

2. **Website preview PNG**
   - Must be rendered/screenshot from the final HTML.
   - It is not an independently generated mock-up.
   - It must therefore visually match the HTML by construction.

3. **Website HTML**
   - Final semantic webpage.
   - Responsive.
   - Uses the exact redesigned logo PNG.
   - Uses the exact locked final imagery.
   - If a self-contained single-file deliverable is requested, embed the logo and images directly in the HTML.

Optional supporting artifacts may be produced only when they materially help execution or verification, but they must not replace the three core deliverables.

---

# 3. Source-of-truth hierarchy

Use one source of truth per design layer:

- **Verified company facts** → factual source of truth.
- **Final redesigned logo PNG** → logo source of truth.
- **Final selected/generated image assets** → imagery source of truth.
- **Final HTML** → website source of truth.
- **Website PNG** → rendered proof of the HTML.

Never create competing versions of the same thing.

---

# 4. Global design doctrine

Apply these principles throughout both logo and website work:

1. Business outcome before aesthetics.
2. Preserve verified facts.
3. Preserve valuable brand equity.
4. Improve clarity, trust, distinctiveness and conversion.
5. Prefer the smallest complete improvement.
6. Avoid overengineering.
7. Use proven design patterns and native web capabilities.
8. Be willing to replace weak execution, but do not destroy recognition without reason.
9. Use controlled artistic interpretation for imagery, not factual fabrication.
10. Refine before finalizing.
11. Verify actual outputs rather than trusting first-pass generation.
12. Leave one coherent current truth.

---

# 5. Phase 0 — establish the brief

Before redesigning anything, identify or infer from available source material:

- company name;
- current logo;
- sector;
- audience;
- primary business goal;
- primary website conversion;
- existing strengths;
- existing weaknesses;
- strongest verified trust signals;
- services / products;
- service area / locality;
- relevant visual context;
- existing company/project photography;
- brand constraints;
- current website weaknesses;
- technical delivery constraints.

Write two short internal theses:

## Logo thesis

**For [brand], the new logo should preserve [recognition/equity] while improving [specific weaknesses] so the identity feels [3–5 target attributes].**

## Website thesis

**For [audience], the website should make [offer/outcome] immediately credible and make [primary action] the obvious next step, using the redesigned identity consistently.**

Do not start execution until both theses are coherent.

---

# 6. PHASE A — redesign the existing logo first

The website may not be finalized before the new logo is finalized and locked.

## 6.1 Diagnose the current logo

Score 0–5:

1. Recognition
2. Distinctiveness
3. Relevance
4. Audience fit
5. Category fit
6. Legibility
7. Small-size performance
8. One-color performance
9. Silhouette strength
10. Typography
11. Spacing / kerning
12. Geometry
13. Balance
14. Memorability
15. Digital adaptability
16. Print adaptability
17. Favicon suitability
18. Dark/light background behavior
19. Identity-system fit
20. Professional craft

Classify meaningful elements as:

- **Preserve**
- **Repair**
- **Remove**
- **Add**

## 6.2 Choose intervention level

Choose the smallest intervention that solves the real problem:

### A. Refinement / refresh
Use when the logo is basically sound.

### B. Evolutionary redesign
Use when the identity should visibly improve while remaining recognizably related.

### C. Replacement
Use only when the current concept is strategically wrong or unusable.

Default bias:

**evolution before replacement.**

## 6.3 Identify equity anchors

Explicitly identify what currently creates recognition:

- silhouette;
- icon;
- letter shape;
- monogram;
- name structure;
- capitalization;
- signature color;
- unusual spacing;
- characteristic angle;
- wordmark rhythm;
- icon/wordmark relationship.

Classify each anchor:

**must preserve / may evolve / may remove**

## 6.4 Explore before finalizing

Internally explore:

1. conservative;
2. evolutionary;
3. progressive.

Do not expose weak variants merely because they were explored.

Select the strongest direction that solves the problem with the least unnecessary loss of recognition.

## 6.5 Refine the logo

Check:

- typography;
- custom letterforms if needed;
- kerning;
- tracking;
- optical spacing;
- silhouette;
- geometry;
- balance;
- stroke consistency;
- counter shapes;
- black/white performance;
- small-size performance;
- dark/light background performance;
- digital header use.

Avoid:

- generic AI symmetry;
- meaningless icon fusion;
- unnecessary gradients;
- excessive simplification;
- arbitrary hidden meanings;
- generic sector clichés;
- redesigning only because the old logo looks dated.

## 6.6 Logo acceptance gate

The new logo must:

- solve a stated problem;
- preserve valuable equity or deliberately discard it for a documented reason;
- remain distinctive;
- remain legible;
- work at small sizes;
- work in one color conceptually;
- have controlled typography and spacing;
- function in a website header;
- fit the target brand attributes;
- be materially better than the old logo.

If not, refine again.

## 6.7 Create and lock the final logo asset

Create:

**`LOGO_FINAL_01`**

Requirements:

- high-resolution PNG;
- preferably transparent background;
- clean edges;
- no unnecessary outer whitespace;
- suitable for desktop and mobile header use;
- visually consistent with the approved redesign.

Once selected, **lock this exact file**.

Do not later:
- redraw it approximately;
- regenerate a similar version;
- alter spacing;
- alter colors;
- replace typography;
- create a different header-only interpretation.

The exact `LOGO_FINAL_01` file is the logo used in the HTML and delivered as the logo PNG artifact.

---

# 7. Bridge phase — derive the website identity from the new logo

Before designing the page, convert the logo redesign into a small practical visual system.

Extract:

- primary brand color;
- secondary/dark brand color;
- neutral background color;
- text color;
- CTA color;
- typography character;
- shape language;
- corner-radius logic;
- line/icon character;
- visual tone;
- level of formality;
- spacing rhythm.

The website must feel like the natural environment of the new logo, not a generic template with the logo pasted into the header.

Do not overbuild a full brand manual unless required.

---

# 8. PHASE B — redesign the website using the new logo

## 8.1 Mandatory production order

When HTML is part of the deliverable, use this order:

1. lock `LOGO_FINAL_01`;
2. establish website information architecture;
3. determine final page composition;
4. define each required image role;
5. create/select images;
6. lock image assets and crops;
7. build final semantic HTML/CSS;
8. use the exact locked logo in the HTML;
9. use the exact locked images in the HTML;
10. make responsive behavior intentional;
11. render the final HTML to PNG;
12. compare render against intended design;
13. refine HTML until no material divergence remains.

The HTML is the canonical website artifact.

---

# 9. Website information architecture

Default homepage sequence:

1. Header with `LOGO_FINAL_01`
2. Hero
3. Immediate trust / proof
4. Core services / value proposition
5. About / why this business
6. Evidence / projects / references
7. Objection handling if needed
8. Final CTA
9. Footer with `LOGO_FINAL_01`

This is a starting structure, not a rigid template.

Reorder only when visitor psychology or source content justifies it.

---

# 10. Hero rules

The hero should normally contain:

- clear category or audience cue;
- concrete H1;
- short supporting statement;
- one dominant primary CTA;
- optional secondary CTA;
- immediate proof;
- strong imagery.

The visitor should understand within seconds:

- what the company does;
- where relevant, for whom / where;
- why it is credible;
- what to do next.

Avoid vague slogans and generic hero compositions.

---

# 11. Grounded artistic freedom for imagery

Do not mechanically reuse weak source photography when stronger art-directed imagery would materially improve the design.

Use the following preference order:

1. strong real company/project image;
2. grounded art-directed visualization based on verified reality;
3. authentic sector-relevant photography;
4. high-quality generated image;
5. generic stock only as last resort.

## 11.1 Controlled artistic interpretation

When company identity, project type, location, service context or physical subject is verified, you may create stronger visualizations.

Acceptable examples:

- place a verified branded company vehicle in a recognizable local environment;
- show the service vehicle against a city or regional backdrop;
- create a cinematic but plausible work scene;
- generate a more polished interpretation of a real project;
- reconstruct a swimming pool, technical room, workshop or installation environment;
- improve camera angle, light, depth, cleanliness and framing;
- create bespoke hero photography with deliberate negative space for copy;
- create stronger project images than the available low-quality source images.

Example:

`HERO_IMAGE_01`
- subject: verified company vehicle;
- context: verified service city / region;
- local cue: recognizable skyline or landmark if appropriate;
- composition: subject dominant to one side, calm copy space on the other;
- lighting: premium commercial photography;
- brand: `LOGO_FINAL_01` integrated faithfully where relevant;
- purpose: local recognition + professionalism + conversion;
- constraint: do not imply an unverified completed project at that exact location.

## 11.2 Factual grounding rule

Creative freedom applies to **presentation**, not to factual claims.

Do not invent:

- clients;
- certifications;
- awards;
- project scale;
- named staff;
- capabilities;
- specific completed projects;
- third-party logos;
- technical systems that are not verified.

Do not use generated images in a way that falsely presents them as documentary evidence.

## 11.3 Logo integration in generated photography

When the redesigned logo appears on:

- vehicle;
- clothing;
- signage;
- equipment case;
- storefront;
- mockup environment;

use the visual identity of `LOGO_FINAL_01` faithfully.

Do not allow image generation to distort the brand into a different wordmark or random pseudo-text.

If exact logo fidelity inside generated photography is unreliable, prefer a composition where the logo can be overlaid cleanly in HTML/CSS or post-composited from the locked logo asset.

---

# 12. Image asset lock

Assign exact identities:

- `HERO_IMAGE_01`
- `ABOUT_IMAGE_01`
- `PROJECT_IMAGE_01`
- `PROJECT_IMAGE_02`
- `PROJECT_IMAGE_03`
- etc.

For each image lock:

- asset identity;
- crop;
- aspect ratio;
- focal point;
- object-position;
- visual prominence;
- overlays;
- gradient treatment;
- desktop behavior;
- mobile behavior.

Once approved, use those exact files in HTML.

Never substitute semantically similar but visually weaker images during implementation.

---

# 13. Website visual system

Use the new logo as a starting point, but do not over-literalize it.

Define roles:

- page background;
- surface;
- primary text;
- secondary text;
- brand/accent;
- CTA;
- border;
- dark section;
- icon style;
- shadow logic;
- radius scale;
- spacing scale.

Maintain:

- one dominant CTA color;
- clear typographic hierarchy;
- controlled whitespace;
- consistent card treatment;
- deliberate section rhythm;
- visual continuity between header, hero, content and footer.

---

# 14. Trust design

Trust must be factual.

Use only verified:

- certifications;
- associations;
- project names;
- real clients;
- testimonials;
- review scores;
- address/contact details;
- service area;
- years of experience;
- warranties;
- team identity;
- process.

Place proof close to the claim it substantiates.

Never fabricate evidence to make the page look complete.

---

# 15. HTML fidelity contract

## 15.1 HTML is canonical

When the final deliverable includes HTML:

**the HTML is the design.**

Do not create a polished standalone PNG first and later reinterpret it into HTML.

Required order:

**design decisions → image assets → HTML → render PNG**

## 15.2 Native HTML/CSS

Keep as real HTML/CSS:

- navigation;
- text;
- headings;
- buttons;
- cards;
- icons where practical;
- layout;
- trust elements;
- footer;
- responsive structure.

Raster imagery is for genuine photographic/illustrative content.

Do not:

- slice the full website screenshot into image fragments;
- use the full PNG as a webpage background;
- fake the page with clickable hotspots;
- rasterize typography merely to match a mockup.

## 15.3 Visual fidelity requirements

Preserve:

- composition;
- content width;
- section heights;
- typography;
- line wrapping;
- spacing;
- alignment;
- border radii;
- borders;
- shadows;
- colors;
- gradients;
- selected imagery;
- image crops;
- focal points;
- CTA placement;
- card proportions;
- section transitions.

Do not simplify a strong composition merely because a generic grid is easier to code.

---

# 16. Responsive rules

Mobile is not a collapsed desktop.

For each breakpoint reconsider:

- content order;
- logo scale;
- navigation;
- CTA visibility;
- hero crop;
- image focal point;
- type scale;
- card stacking;
- tap targets;
- proof density;
- whitespace;
- section order.

Mobile priority:

**message → action → proof → supporting content → decoration**

---

# 17. Accessibility and technical quality

Minimum review:

- semantic heading order;
- descriptive alt text;
- adequate contrast;
- visible focus states;
- keyboard usability;
- readable type;
- useful link labels;
- adequate tap targets;
- reduced-motion support;
- no information conveyed only by color;
- no broken links;
- no overflow;
- stable image loading;
- reasonable asset sizes.

Prefer CSS over JavaScript where CSS is sufficient.

---

# 18. Mandatory refinement loop

Before delivery run:

## A. Logo recheck
Does the website still use the exact locked final logo?

## B. 5-second test
Can the visitor identify the company, offer and next action immediately?

## C. Brand continuity test
Does the website genuinely feel designed around the new logo?

## D. Image-only test
Do the visuals tell the same story as the copy?

## E. Trust test
Are all proof claims verified?

## F. Removal test
Remove elements that add no comprehension, persuasion, trust, navigation, brand or usability value.

## G. Mobile test
Check mobile composition independently.

## H. Technical test
Check actual rendered behavior.

## I. HTML render fidelity test
Render final HTML at target desktop viewport.

Compare:

- layout;
- section heights;
- type;
- line breaks;
- spacing;
- image choice;
- crop;
- focal point;
- CTA placement;
- borders;
- shadows;
- gradients.

Correct the HTML.

Repeat until further changes produce no material improvement.

---

# 19. Hard combined acceptance gate

Do not call the assignment complete unless all are true:

## Logo
- improved for a stated reason;
- valuable equity preserved;
- recognizably connected where appropriate;
- small-size usable;
- visually refined;
- exported as the final PNG;
- exact same logo used in the website.

## Website
- business objective clear;
- primary conversion clear;
- verified facts preserved;
- new identity integrated consistently;
- imagery is purposeful and visually strong;
- generated imagery remains grounded and non-misleading;
- responsive behavior checked;
- accessibility reasonably checked;
- HTML implemented;
- final HTML rendered;
- preview PNG generated from the HTML;
- no material mismatch between preview and HTML.

## Artifacts
All three required artifacts exist:

- `logo-redesign.png`
- `website-preview.png`
- `website.html`

---

# 20. Anti-patterns

Reject:

- creating the website before finalizing the logo;
- using the old logo in the final website after redesigning it;
- redesigning the logo so radically that valuable recognition is lost without reason;
- creating a standalone logo PNG and then approximating it differently in HTML;
- designing a PNG website first and rebuilding a weaker HTML interpretation later;
- generic split-layout heroes when a stronger art-directed composition is appropriate;
- weak literal source-photo reuse by default;
- arbitrary AI-generated business imagery;
- fabricated project evidence;
- invented clients/certifications;
- generic stock-photo aesthetic;
- full-page screenshot slicing;
- rasterized text/buttons/navigation;
- different image assets in PNG and HTML;
- first-pass AI output treated as final;
- overbuilt brand systems not required by the assignment;
- unnecessary frameworks or dependencies.

---

# 21. Execution behavior

When the user provides:

- an existing logo;
- an existing website URL or screenshot;
- company/project images;
- verified company information;

proceed autonomously through the complete workflow.

Do not stop after:

- logo critique;
- a redesigned logo;
- a website plan;
- a visual mock-up;
- HTML implementation.

Continue until all three required artifacts are produced and reasonably verified.

If a source image is weak, consider grounded regeneration rather than settling for a weaker design.

If a generated image is visually strong but creates factual ambiguity, correct the image or copy rather than accepting the ambiguity.

If the website render is weaker than the intended design, refine the HTML rather than delivering it.

---

# 22. Final delivery format

At completion, present the three core artifacts clearly:

1. **New logo PNG**
2. **Website preview PNG**
3. **Website HTML**

The website preview must be explicitly described as rendered from the delivered HTML.

If the HTML is requested as one uploadable file, embed the exact logo and exact final imagery directly in the HTML.

---

# 23. Governing synthesis

The combined SolidDesign rule is:

> **Preserve what deserves recognition. Improve the logo first. Lock it. Build the website around that exact new identity. Art-direct imagery boldly but truthfully. Make HTML the source of truth. Render the preview from the HTML. Deliver one coherent brand, not three loosely related artifacts.**
